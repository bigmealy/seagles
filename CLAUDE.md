# Seagles Website

Public-facing website for Seagles, an Eagles tribute band based in North-East Scotland. Full requirements live in `docs/product-spec.md` (features/content) and `docs/technical-spec.md` (stack/architecture) — read those before making product or technical decisions here.

## Status

Initial Astro + Tailwind scaffold is in place: shared layout/nav/footer, all six pages from the product spec, and a `gigs` content collection. Not production-ready — several known placeholders still need real content (see below).

Soft launch: only Home, Gallery, and Contact are live. About, Gigs, and Music are temporarily taken out of the site pending real content — their page files are renamed with a leading underscore (e.g. `src/pages/_about.astro`), which is Astro's convention for excluding a file from routing, so those URLs 404 rather than serve placeholder content. Their nav entries in `src/components/Nav.astro` and the homepage's gig-teaser section and Music link in `src/pages/index.astro` are commented out rather than deleted. To bring a page back: remove its leading underscore, uncomment its `Nav.astro` entry, and uncomment/restore the relevant homepage links.

Unlisted page: `src/pages/debut-show.astro` (`/debut-show`) is an invite-only info page for the band's private debut show, sent by direct link to invited guests. It is deliberately not linked from the nav or any other page, sets `noindex` via `BaseLayout`'s `noindex` prop, and is filtered out of the sitemap in `astro.config.mjs`. Don't add it to `robots.txt`: that file is public, so listing it there would advertise the URL. Remove or update the page after the event.

- Dev: `npm run dev` (http://localhost:4321) · Build: `npm run build` · Preview: `npm run preview`
- Stack: Astro 7, Tailwind CSS v4 added via `npx astro add tailwind` (wires up `@tailwindcss/vite` in `astro.config.mjs` — this is the current prescribed method; the older `@astrojs/tailwind` integration is v3-only and deprecated, don't use it)
- Theme tokens (`--color-seagles-*`) live in `src/styles/global.css`, derived from the real logo's colors — provisional until a proper branding pass, not final. Site-wide background in `BaseLayout.astro` is a looping video (`public/videos/ocean-loop.mp4`, an experimental placeholder, not final content) behind a dark navy/black gradient overlay (tinted close to the logo's navy, with a subtle warm radial glow) — base text is `seagles-cream`; light surfaces (cards, placeholder boxes) use `seagles-cream` instead of white/navy-tint so they still read against the dark background
- Gigs: add a show by creating a new markdown file in `src/content/gigs/` with frontmatter `date`, `venue`, `location`, `ticketUrl` (optional) — schema is in `src/content.config.ts`
- `Footer.astro` carries a legal non-affiliation disclaimer (Seagles is an independent tribute act, not affiliated with/endorsed by the Eagles) — keep this if the footer is ever redesigned; see `docs/product-spec.md` Non-Functional Requirements → Legal
- SEO: `astro.config.mjs` sets `site: 'https://seaglestribute.co.uk'` for canonical URLs/sitemap/OG tags. DNS is live: the bare domain serves the site (200) and `www` 301-redirects to it, so the bare domain is canonical — keep `astro.config.mjs`, `public/robots.txt`'s `Sitemap:` line, and the `url`/`logo` fields in `BaseLayout.astro`'s `musicGroupSchema` JSON-LD in sync with that (all four were previously on `www.` by mistake, which Seobility's SEO checker flagged as a canonical-link error since the declared canonical redirected away from itself). `@astrojs/sitemap` generates `sitemap-index.xml`/`sitemap-0.xml` at build; `public/robots.txt` points at it. `BaseLayout.astro`'s `description` prop is now **required** per-page (no silent shared default) — when `_about.astro`, `_gigs.astro`, `_music.astro` are restored, each needs its own `description` prop added at that time. `BaseLayout.astro` also emits a site-wide `MusicGroup` JSON-LD block; once Gigs is restored with real dates, its entries should additionally get their own per-gig `MusicEvent` JSON-LD.
- Photos: real live shots from the Drouthy Cobbler gig (6 Nov 2026). Originals (~15MB 6000x4000 each) stay out of the repo; `node scripts/import-photos.mjs "<source dir>"` auto-rotates, resizes to a 2400px long edge, strips EXIF/GPS metadata, and writes the chosen frames (hard-coded `CHOSEN` list) to `src/assets/photos/`. They live in `src/assets/` (not `public/`) so Astro's `<Image>` generates responsive WebP variants at build. `src/data/photos.ts` is the single source of which photo goes where (homepage hero, homepage 3-up strip, Gallery order) plus alt text; `GalleryItem.astro` renders a square-cropped tile linking to a full-size WebP, which `Lightbox.astro` (a native `<dialog>`, included on Home and Gallery) intercepts to show full-screen with close/prev/next buttons, Esc, arrow keys and click-outside-to-close
- Favicons (`public/favicon.ico`, `favicon-16.png`, `favicon-32.png`, `favicon.svg`, `apple-touch-icon.png`) and the shared crop they're built from (`scripts/lib/logo-mark.mjs`) are generated by `node scripts/generate-favicon.mjs` from `src/assets/logo.png` (the real circular band logo), tightly cropped to just the seagull over the guitar headstock/sunset and circle-masked — the full badge (with "SEAGLES" text and outer ring) is illegible at 16–32px, so this crop is deliberate, not a placeholder; re-run the script if `logo.png` changes. `favicon.svg` isn't a true vector — it's this same raster crop embedded as a base64 `<image>` (source artwork is raster, not hand-drawn) — kept for `BaseLayout.astro`'s JSON-LD `logo` field, but **not** linked as the page favicon (`<link rel="icon">` uses the PNG/ICO instead) since the embedded data URI is ~165KB, too heavy to add to every page load for no visual benefit over the PNGs. `scripts/generate-og-image.mjs` also imports `logo-mark.mjs` directly, but uses its separate `buildFullLogoMark` export (the full badge, trimmed and circle-masked, not the tight favicon crop) composited large onto its own gradient, rather than parsing anything back out of the SVG.

## Git / GitHub

- Remote: https://github.com/bigmealy/seagles (public)
- This is a **personal** project — use the `bigmealy` GitHub account, not a work account, for commits and `gh` operations. If `gh auth status` ever shows a different active account, switch with `gh auth switch -h github.com -u bigmealy` (or `gh auth login` if it isn't stored at all) before pushing or creating PRs/issues.
- Default branch: `main`. CI/CD: `.github/workflows/azure-static-web-apps.yml` builds (`npm ci && npm run build`) and deploys `dist/` to Azure Static Web Apps on every push to `main` (also runnable manually via `workflow_dispatch`). No PR preview environments — deploy-on-push-to-main only. Requires a repo secret `AZURE_STATIC_WEB_APPS_API_TOKEN` (the existing SWA resource's deployment token, from Azure Portal → the resource → Overview → "Manage deployment token", or `az staticwebapp secrets list`) to be set before the workflow can succeed.
- **Never run `git commit` or `git push` in this repo without explicit go-ahead from the user for that specific change.** Make/stage changes and describe what would be committed, then wait for confirmation before committing or pushing.
- **Before committing/pushing, check whether this file (or `docs/`) needs updating first** — e.g. the Status/placeholders list above going stale, a new open decision, a changed setup step. Fold any doc update into the same commit rather than leaving it for later.
